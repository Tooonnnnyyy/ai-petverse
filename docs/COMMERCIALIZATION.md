# AI Petverse 商业化边界（Web MVP）

## 目标

用户即使没有付费，也应始终可以和自己的猫狗互动。核心陪伴不能因为 AI quota 用尽而被锁死；否则会破坏产品的治愈承诺，也会把宠物依恋变成付费压力。

## 推荐计划

| 计划 | 永久保留 | 可收费增量 |
| --- | --- | --- |
| Basic | 本地猫狗、照片本地参考、房间互动、基础旅行/课程、基础纪念品 | 每周少量云端生成额度；基础场景 |
| Premium | Basic 全部 | 更多照片动作包、AI 生成短片/场景、更多课程和旅行路线、较高额度 |
| Max | Premium 全部 | 更高生成额度、多人/社交房间、优先队列、可选自定义场景 |

## 不采用的收费规则

- 不因“本周 AI 用完”而禁止用户抚摸、喂食、说话或查看本地宠物。
- 不用“你的宠物因你没登录而抑郁/生病”推动续费。
- 不按食物价格推断营养或健康；食物价格是游戏道具属性，健康状态只能是可恢复的游戏模拟。
- 不把真实兽医诊断、药物建议、紧急提醒伪装成游戏通知。

## 额度与服务边界

AI 请求必须在服务端按 account、provider、model、feature、周期记录用量；浏览器本地 demo 不显示“已扣费”或“已发送邮件”。额度耗尽时返回本地 fallback，并清晰显示恢复时间/升级选项。计划、价格、税费、退款和自动续费在 Stripe/Apple/Google 接入前不写死在前端。

## 真实宠物照护

“心情低落”“需要休息”“照护待办”只表示游戏状态，不等同于抑郁或疾病。涉及真实健康问题时，产品只提供联系兽医/急诊的通用入口；注册邮箱和 Web Push 需要明确 opt-in、退订、删除和地区合规实现。

## 可迭代数据结构

当前 Web MVP 使用 `LIFE_RULES.version = 1` 的本地成长规则：每日信号上限、旅行稀有概率、pity、课程成本、商店成本集中在 `web/src/game/life.ts`。未来计划升级必须通过版本迁移，不覆盖旧存档；支付、远端账号、社交资料和原始宠物照片属于独立隐私边界。
